# 小红书 WebView 下载无响应与截止时间高亮异常

> 本文由 AI 辅助整理，并由项目负责人审核。日志中的 IP、链接令牌及其他客户信息均已脱敏。

## 摘要

在解决 Chrome 92 WebView 无法完成前端初始化的问题后，Android 用户又反馈：资料领取页面能够正常显示，但点击“下载我的专属资料”没有可见反应；页面中的截止时间高亮也显示成了大块实色背景。

生产访问日志确认点击操作已经到达下载接口，因此按钮事件、前端路由和服务端下载入口均已执行。同一用户随后将相同链接放到 Android 独立浏览器中打开并成功下载，将问题范围收敛到小红书 APP 内置 WebView 的文件下载交付链路。由于没有取得设备端控制台、下载管理器或 WebView 回调日志，WebView 内部具体中断点仍未确认。

截止时间高亮异常与下载链路相互独立。Chrome 92 兼容构建中的 `color-mix()` 降级结果没有保留预期的浅色背景，截图中呈现为大块主题色。将关键提示改为固定浅色背景后，旧版内核与现代浏览器的表现一致。

本次处置没有改变文件下载接口。页面在识别到 Android 或 iOS 应用内置 WebView 时，明确引导用户使用独立浏览器：

- 苹果用户：点击右上角菜单，选择“Safari打开”。
- 安卓用户：点击右上角菜单，选择“浏览器打开”。
- 如果应用没有对应菜单项，复制链接到喜欢的浏览器；推荐 Safari、Edge 或 Chrome。

这是一项可靠的绕行和用户引导，不代表小红书 WebView 自身的下载能力已经被修复。

## 用户可见现象与影响

- Android 小红书内置浏览器中，页面、资料名称和下载按钮均可正常显示。
- 点击下载按钮后没有可见反馈，用户无法判断文件是否保存。
- 同一链接在 Android 独立浏览器中能够成功下载。
- 截止时间文字附近出现面积过大的实色主题背景，影响可读性。
- 服务健康、链接状态和已生成文件均未出现异常。

影响范围限定为应用内置 WebView 中的文件下载体验，以及旧版浏览器中的截止时间高亮样式。现有证据不支持将问题扩大为资料生成失败、文件缺失或全平台下载故障。

## 证据链

### 下载请求已经触发

生产访问日志中能够找到受影响会话发出的 `/download` 请求。这说明：

1. 页面 JavaScript 已经完成初始化。
2. 下载按钮的交互事件已经触发。
3. 请求已经离开 WebView 并到达 nginx/应用下载入口。

因此，“没有反应”描述的是 WebView 没有向用户交付或展示文件，而不是按钮未绑定、点击事件未执行或服务端没有收到请求。

进入事故文档的日志信息只保留请求类型和结论；客户端 IP、发货链接令牌、手机号、订单号和会话信息均不记录。

### 独立浏览器成功下载

在首次失败后的用户复测中，相同 Android 设备通过独立浏览器成功完成下载。相同链接、文件和服务端入口能够工作，进一步排除了以下方向：

- 链接失效或过期；
- 专属文件尚未生成；
- 下载接口全局不可用；
- Android 系统整体无法保存该文件。

该对照实验支持将故障边界定位在小红书 WebView 对下载响应、文件保存或外部下载管理器的处理环节。

### 截止时间高亮

异常截图显示，截止时间附近的背景变成了不符合设计预期的大块主题色。修复前的样式使用：

```css
background: color-mix(in srgb, var(--accent) 10%, white);
```

生产构建 CSS 与 Chrome 92 模拟验证表明，该写法的旧内核降级表现不可靠。修复后使用固定颜色：

```css
background: #f6f0ee;
```

截止时间仍使用主题色文字，浅色背景不再依赖 `color-mix()`。

## 根因与未知边界

### 已确认

- 下载点击能够到达服务端下载入口。
- 相同链接在 Android 独立浏览器中能够成功下载。
- 故障与小红书应用内置 WebView 的下载交付行为相关。
- 截止时间高亮异常来自旧版内核中的 CSS 兼容性表现。

### 尚未确认

- WebView 是丢弃了附件响应、拦截了导航，还是没有正确调用系统下载管理器。
- 设备是否产生了仅在 WebView 控制台可见的异常。
- 小红书不同版本、厂商 WebView 和 iOS WKWebView 是否具有完全相同的失败机制。

User-Agent 只能用于有针对性的提示，无法百分之百准确识别所有应用容器。最终页面对已识别的 WebView 同时展示苹果和安卓两种操作说明，避免错误的平台判断让用户无路可走。

## 修复内容

### 1. WebView 识别

[`lib/browser.ts`](../../lib/browser.ts) 增加平台识别：

- Android：匹配 `wv` 标记，或 Android UA 中的 `Version/<major>` WebView 特征。
- iOS：匹配 iPhone/iPad/iPod 和 AppleWebKit，同时排除 Safari、Chrome、Firefox、Edge 与 Opera 的独立浏览器标记。
- Edge、Chrome 和 Safari 独立浏览器不显示警告。

### 2. 无歧义的用户引导

[`components/BuyerPortal.tsx`](../../components/BuyerPortal.tsx) 在识别到 WebView 时显示：

> 请换到浏览器下载  
> 当前使用的是应用内置浏览器，直接下载可能没有反应。  
> 苹果用户：点击右上角菜单，选择“Safari打开”。  
> 安卓用户：点击右上角菜单，选择“浏览器打开”。  
> 也可以复制链接到你喜欢的浏览器。推荐 Safari、Edge 或 Chrome。

提示移除了外部跳转图标和模拟三点符号。页面没有直接执行跳转，避免图标让用户误以为点击后会自动打开新页面；菜单符号也不再依赖字体字距和不同应用的图标样式。

### 3. 旧版浏览器安全的高亮样式

[`app/globals.css`](../../app/globals.css) 将截止时间高亮的背景改为固定浅色，并为 WebView 提示增加移动端布局。

### 4. 自动化覆盖

- [`tests/browser.test.ts`](../../tests/browser.test.ts) 覆盖 Android/iOS WebView 识别和独立浏览器排除。
- [`tests/buyer-portal-ui.test.ts`](../../tests/buyer-portal-ui.test.ts) 固定最终提示文案、无歧义图标要求和 Chrome 92 安全的截止时间背景。

## 回滚

如果提示对正常浏览器产生误报，或页面布局出现不可接受的回归，使用标准 release 回滚流程恢复到上一完整版本。回滚前后均需确认：

1. `/opt/prep-trove/current` 指向预期 release。
2. 应用健康接口返回 `{"ok":true}`。
3. 资料数据目录和 SQLite 数据库没有被代码 release 覆盖。
4. 管理配置完整性保持不变。

回滚提示不会让小红书 WebView 获得更可靠的下载能力，因此业务侧仍应保留“改用独立浏览器”的人工支持话术。
